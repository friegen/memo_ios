### 判断したこと
- **ターゲット名は `IrodoriNotes`**: Swift ではターゲット名がモジュール名になる。`Memo` にすると、ドメインモデルの `Memo` 型と名前がぶつかるため
- **Xcode 27 の新しいプロジェクトの形式（`project.xcproj`）のまま**: JSON で読みやすく、差分も見やすい。説明書がないため、項目名は Xcode のツールから調べた（テストの種類は `bundle.unit-test` / `bundle.ui-testing`）
- **Mac・Vision Pro で「iPhone 版をそのまま動かす」設定も切った**（`SUPPORTS_MAC_DESIGNED_FOR_IPHONE_IPAD` などを NO）: 確認していない環境で配られないように

- **文字列のキーは Android の strings.xml の name**（例: `app_name`）: 訳を持ってくるとき・見比べるときに対応が分かるように
- **Swift の設定はテンプレートのまま**（Swift 5 モード・何も書かなければメインスレッドで動く設定）: 重い処理（DB・HTML の変換など）だけを明示的に別スレッドにする

### 判断したこと
- **テーブル・列・保存する値は Android と同じ**: 列の名前・型、色の名前（red など）、並び順やテーマの保存名（`UPDATED_AT`・`DARK` など）、設定のキー（`theme_mode` など）をそろえた。将来バックアップを Android と共通にしやすくするため（テストで確かめている）
- **DAO は `enum` の中の関数（SQL を書く）**: Android の DAO の SQL をそのまま移せて、見比べやすいため。Repository は DB（`AppDatabase`）だけを受け取る。UseCase・Repository に protocol は作っていない
- **一覧で本文を読まない決まりも同じ**: iOS の SQLite には Android の「1行 約2MB」の上限はないが、一覧が重くならないように同じ作りにした
- **データの型はメインスレッドに縛らない**（`nonisolated`）: このプロジェクトは「何も書かなければメインスレッドで動く」設定なので、DB の中で使う型（レコード・ドメインモデルなど）にだけ印を付けて、DB の処理を別スレッドで動かせるようにした（Android の Dispatchers.IO にあたる）
- **設定の変化の監視**: UserDefaults が変わったときの知らせ（`UserDefaults.didChangeNotification`）を受けて、値が変わったときだけ流す（Android の DataStore の Flow ＋ distinctUntilChanged と同じ動き）
- **名前の並び順**: 端末の言語に合わせた比べ方（Android の Collator にあたる `String.compare(_:locale:)`）
- **時刻**: `AppClock` は、テストで継承して時刻を固定できるようにした（protocol は使わない）
- **HTML の変換はステップ4・5に回した**: 画面（UITextView の装飾）とつながる部分が多いため。Android もステップ4・5で作っている
- **ライセンスの一覧は手で管理し、テストで足し忘れを見つける**: `Package.resolved` に載っているパッケージが `licenses.json` にすべてあるかを `LicensesTests` が確かめる

### 書式の決まり（Android 版 v1.5・v1.9 と同じ）
- 右上の書式ボタン（オン／オフ）でパネルを開閉。パネルの × でも閉じる。選択を外してもパネルは閉じない
- 文字を選んでいるとき: 選んだ文字の書式を、選んだまま何度でも付け外しできる
- カーソルだけのとき: これから入力する文字の書式を選ぶ。パネルを開いた直後・カーソルを動かした後は、カーソルの直前の文字の書式から始まる
- パネルを閉じているときに入力した文字は書式なし（装飾の直後や途中に入力しても引き継がない）
- 太字・斜体・下線は、選んだ範囲全体に付いていれば外し、一部でも付いていなければ全体に付ける
- 色は名前で保存し、表示する色はライト／ダークで切り替える
- 他のアプリからの貼り付けは文字だけ（貼り付けた文字には、パネルの状態の書式が付く）

### 判断したこと
- **書式は「意味の印」と「見た目」を分けて持つ**: 本文の1文字ずつに「太字」「赤」などの印を付け、保存（HTML）は印だけから作る。見た目（フォント・色）は印から作り直す。こうすると、文字の大きさを変えても書式が消えず、日本語の変換中の下線などキーボードが一時的に付ける見た目が保存に紛れ込まない（Android で起きた問題）
- **これから入力する文字の書式は iOS の typingAttributes で付ける**: 日本語の変換中の文字・貼り付け・音声入力にも同じように効く。iOS はカーソルが動くと typingAttributes を直前の文字の書式に戻すので、そのたびにパネルの状態に合わせ直す
- **斜体は文字を傾けて表示する**（Android と同じ）: 日本語のフォントには斜体がないため。入力欄は、文字を傾ける指定が描かれる従来の描き方（TextKit 1）を使う（新しい描き方 TextKit 2 では傾かなかった。画面を撮って見つけた）
- **色の段は横にスクロール**（Android と同じ）: 既定＋10色は iPhone の幅に入りきらないため。押せる大きさ（44pt）を保つ
- **iOS 標準の「書式（B/I/U）」メニューは出さない**: 貼り付けを文字だけにする設定で、標準の書式メニューも出なくなる（Android で「選択時メニューの書式」を廃止したのと同じ。書式はパネルだけで変える）

### 確認結果
- 単体テスト 140件・UI テスト 17件すべて成功（iOS 27.2・iOS 26.0）、ビルドの警告なし
  - 追加の単体テスト: `MemoHtmlTests`（Android の MemoHtmlTest の書式の部分: 各書式・重なった装飾・往復・知らない色の名前・閉じていないタグ・絵文字・Android で保存した HTML を読んで書き戻すと同じ）、`TextStylerTests`（Android の TextStylerTest と同じ: 付け外し・一部なら全体に・途中を外す・太字＋斜体から太字だけ外す・色・カーソルの直前の書式）、`MemoTextAttributesTests`（太字・斜体・下線・色の見た目、10色ともライトとダークで違う色、文字の大きさを変えても書式が残る、入力欄の描き方）
  - 追加の UI テスト（`FormatUITests`）: 書式ボタンと × でパネルが開閉、太字＋赤で入力 → パネルを閉じて入力 → 戻って開き直しても、選ぶとパネルが太字・赤／書式なしを表示、選んだまま下線を付けて外す
- 画面を撮って確認（日本語、ライト・ダーク）: 10色の文字（どちらの背景でも読める）、太字・斜体・下線、書式パネル（キーボードの上／キーボードを閉じたとき画面の下）、書式ボタンのオン

### ユーザーに確認してほしいこと（Xcode で `IrodoriNotes-iPhone17` に入れて）
1. 右上の書式ボタン（「Aa」や「あぁ」のアイコン）でパネルが開閉する（オンのときボタンが青）。× でも閉じる
2. 文字を選んで B・I・U・色を付け外しできる。選んだまま続けて変えられる
3. パネルを開いてカーソルだけの状態で B や色を押してから入力 → その書式で入る。カーソルを動かすと、その位置の直前の文字の書式に変わる
4. パネルを閉じて、太字や色の付いた文字の直後・途中に入力 → 書式なしで入る
5. **日本語入力（変換中）でも上の動きが同じで、変換中の下線がメモに残らない**（シミュレーターでは日本語のキーボードで確かめる。メニューの I/O ＞ Keyboard ＞ Connect Hardware Keyboard のチェックを外すと画面のキーボードが出る）
6. 書式を付けて戻る → もう一度開いて書式が残っている
7. 色の段を横にスクロールして、茶・グレーも選べる
8. ダークモードに切り替えて（⇧⌘A）、色付きの文字が読める（編集画面を開いたまま切り替えても色が変わる）
9. Safari などから装飾付きの文字をコピーして貼り付け → 文字だけ入る（パネルを開いていれば、パネルの書式が付く）

### 判断したこと
- **ロックし直すのは、アプリがバックグラウンドに回ったとき**（iOS の `scenePhase == .background`）。Face ID の画面・通知センター・コントロールセンターでは `.inactive` になるだけなので、ロックし直さない（requirements.md のとおり）
- **アプリの切り替え画面に中身を映さない**: ロックした中身の画面が出ている間、アプリが `.active` でなくなったら起動画面と同じ見た目（ロゴ）で覆う。iOS はアプリから離れる瞬間の画面を切り替え画面に使うため。スクリーンショットは止められない（requirements.md 🟡）
- **パスコードがないとき**: 「パスコードが必要です」の案内（設定アプリの「Face ID とパスコード」〔または「Touch ID とパスコード」〕の場所を文で伝える）。設定を開くボタンは付けない（iOS では開けないため。requirements.md 🟡）。ロックしたメモ・フォルダを開こうとしたときは、案内を閉じたら画面も閉じる
- **ロックしたフォルダの中のメモ・フォルダは、もう一度は聞かない**（フォルダに入るときに認証済み）。メモ自体のロックは開くたびに聞く（Android と同じ）
- **中身を隠している間は、並び替え・＋・書式のボタンを押せなくする**
- ゴミ箱の鍵のアイコン・認証なしの復元／完全削除はステップ8のまま（Android と同じ）
